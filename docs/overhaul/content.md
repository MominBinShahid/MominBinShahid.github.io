## Tagline — "Applied AI", researched 2026-09-21

**"FULL-STACK & AI" is out.** Momin judged it unprofessional and a corpus of 31,607 HN
job postings plus 3,442 live reqs backs him — but not for the reason either of us assumed.

**The problem is not the word "full-stack".** Anthropic posts *"Staff+ Software Engineer,
Full-stack"*. OpenAI attaches *"Full Stack"* to Codex and Agents. Stripe, Linear and Ramp
all use it at staff level. It is not a seniority downgrade. Its share is falling (14.8 →
10.3 per 100 postings) but what replaced it is **Product Engineer** (1.1 → 3.4, tripled),
not AI.

**The problem is the ampersand.** Two shouted skill buckets joined by `&` is job-board
grammar, and it is the modal self-description of a job *seeker* — fourteen separate HN
"who wants to be hired" posts use "full-stack and AI engineer", from people with 3, 6 and
16 years.

**LOCKED 2026-09-21: `Staff Software Engineer · Applied AI + Full-Stack`.**

Goes on the banner, the website, LinkedIn, the GitHub profile — every surface, same
words. Order matters editorially, not for search: keyword and Boolean matching are
position-independent, so both terms are found either way. Applied AI leads because it is
the current work and the differentiated term (0.6 postings per 100, against full-stack's
10.3). Full-stack follows because it is the foundation and the most-searched term in the
corpus. `+` reads as *and also*, which is exactly the claim.

Rejected: adding "Dev" or "Developer" at the end — it would put two role nouns in one
line and "developer" reads a rung below "engineer". Also rejected: comma-separating the
three terms, which is job-board grammar.

**Longer form for LinkedIn and meta descriptions**, where there is room:

> Staff Software Engineer · Applied AI + Full-Stack
> Eight years shipping production software. Now building AI agents that run against real
> customer work.

**Honest limit, stated to Momin:** "Applied AI" is *not* yet a society-wide norm — 0.6 per
100 postings, near zero before 2026. Engineers and hiring managers at AI-forward companies
read it fluently; a generalist HR screener at a traditional enterprise may not. It survives
that because the line degrades gracefully: anyone who misses "Applied" still reads *Staff
Software Engineer*, *AI*, *Full-Stack*.

**Where the keywords actually do their work** — not the headline. LinkedIn's job-title
filter is Boolean over **Experience entries**, and keyword matching runs against **Skills**.
So: Experience title stays `Staff Software Engineer`; Skills carry Full-Stack, AI
Engineering, Applied AI, LangChain, Python, React, Node.js; the headline is what a human
reads after you have already surfaced. Optimising the headline for ATS is a category error.

## Current architecture — what the site actually is

Read from the code, not assumed. This matters because the first design round
invented a landing page the site has never had.

**There is no landing page.** `src/pages/index.jsx` renders `<AboutMe />`,
`<Skills />` and `<Quotes />` inside the shell. Home *is* the about page.

**Every page shares one shell:**

```
Header          nav · theme toggle · settings drawer (wrench icon)
├─ Sidebar      sticky via AntD Affix, 6/24 cols on lg, 9/24 on md
│    avatar
│    name — "Momin" bold, "Bin Shahid" lighter
│    two badges — designation, and Sastaticket.pk (linked)
│    socials row
│    contact block
│      📞 phone (tel:) + WhatsApp icon
│      🎂 Dec 13, 1995 → links to Wikipedia's December 13
│      🏡 Karachi, Pakistan → links to Wikipedia
│      📧 email, HTML-entity encoded, text injected via CSS
│    Download CV button
└─ Content      18/24 cols on lg, in a rounded box
```

On mobile the sidebar renders only on the home page. The Affix is active only
when the viewport is wider than 767px *and* taller than 765px.

**Page by page:**

| Page | Contains |
|---|---|
| Home | `AboutMe` — "About Me 👋" title, two `dangerouslySetInnerHTML` paragraph blobs, six tiles · `Skills` (disabled) · `Quotes` |
| Blog | "Blog" title, AntD `Row`/`Col` grid of `PostCard`, 3-up on lg, `Empty` state when none |
| Post | title, banner image (`gatsby-image` fluid), article HTML, Disqus (off in prod) |
| Tags | tag list derived from published posts, joined with config colours + per-tag images |
| Tag | banner, description, PostCard grid |
| Resume | `react-pdf` viewer, own layout, no shell |
| Contact | illustration, form, socials grid |
| 404 | illustration, Go Back button, full-width sidebar variant |

**The thing to redesign is therefore a profile rail and a content column** — not
a marketing page. Any direction may keep, invert or replace that structure, but
home must read as a personal page.
