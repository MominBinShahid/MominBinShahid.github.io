## Post 1 — the Gatsby → Astro migration. **Published.**

The blog's own origin story, and the reason it isn't launching empty.

### What it is about

Not a changelog. It needs a thesis, and the honest one is: *the hard part of a migration
is never the framework, it is finding everything the old framework was quietly doing for
you.* Every good detail we have supports that.

### Material worth using — all of it real, all of it from this project

- **A file in a repo survives a framework change; a file emitted by a plugin does not.**
  The single most useful line to come out of this. Credit where due: the framing came
  from the parallel MealUnits session.
- **`robots.txt` was generated by a plugin and existed on no branch.** It carries the
  only crawl entry for a *different* site on the same origin. Losing it would have been
  silent search death for MealUnits, with nothing failing visibly.
- **`gatsby-plugin-manifest` emitted far more than the manifest** — 8 icon PNGs, the
  32px favicon, `theme-color`, and 8 `apple-touch-icon` links. Drop the plugin and the
  favicon 404s. None of it tracked in git.
- **`.nojekyll`.** Astro puts hashed assets in `/_astro/`; Jekyll skips underscore paths.
  Without that zero-byte file the whole site serves unstyled — and still returns 200, so
  a smoke test passes. Gatsby never used underscore paths, so this had never bitten.
- **`/rss.xml` had been 404ing for years** because `config.js` advertised a feed no
  plugin generated. Nobody noticed. Found only by enumerating instead of assuming.
- **The service worker.** `gatsby-plugin-offline` registers at `/`, so it sees the whole
  origin. `caches.keys()` is origin-wide: a naive cleanup would have deleted MealUnits'
  cached insulin data. The fix is an allowlist, never a denylist.
- **The dark-mode invert hack.** The old site's dark mode is a whole-page
  `invert(92%) hue-rotate(180deg)`, which forces a counter-filter on every emoji and
  image. A good concrete example of one shortcut generating a chain of workarounds.
- **The enumeration lesson**, which is really the post's method: every one of these was
  found by listing what the build actually emitted, not by remembering. Two claims in
  this project were wrong until they were checked — "nine touch icons" (it is eight) and
  a confident explanation of an emoji difference that turned out to be two different
  artwork generations, not a CSS filter.

### Deliberately leave out

Anything that reads as a feature tour, dependency version tables, and the entire
"why I left framework X" genre. The framework comparison is not the story; the plumbing
underneath it is.

### An honest question to settle before publishing

The old blog has **zero of Momin's own posts** — all nine in `content/` are the template
author's demo content. So this was never a content migration. Saying that plainly makes
the post better and more honest, but it is Momin's call whether it goes in. **Ask.**

### Tone

Written by a working engineer, not by a content machine. Specifically:

- First person, past tense, plain words. "I found", not "it was discovered".
- Concrete over abstract. A filename beats a noun phrase every time.
- **No em-dash chains, no bolded mini-headers inside paragraphs, no perfectly parallel
  tricolons, no exhaustive enumeration.** Those are the tells.
- Adequate length. Long enough to carry the lesson, short enough to finish. Roughly
  1,000–1,400 words. If a section has no learning in it, cut the section.
- It should read like something Momin wrote.

### Secondary job: exercise the renderer

This post should deliberately use every feature the blog needs to support, so it doubles
as a rendering test:

| Feature | Why it belongs naturally |
|---|---|
| Fenced code blocks, several languages | config snippets, the `caches.keys()` fix |
| A table | the emitted-files audit |
| Footnotes | Sätteri has them built in; good place to prove it |
| Headings / anchor links | it is a long-form post |
| An image or two | before/after, or the emitted-file audit |
| Inline code | filenames throughout |
| A blockquote | the plugin/repo line |

## The mechanism underneath both

Astro content collections with a typed schema and a `published: boolean` field,
**defaulting to `false`**.

**Renamed from `draft` on 2026-09-21, at Momin's push-back, and he was right.** Checked
first rather than assumed: nothing in Astro 7 reads either name. There is no
`markdown.drafts` config option, nothing in the content layer, nothing in the public
types — the old built-in was removed, so this has always been our field filtered by our
own code. `draft` survives only as a habit copied out of templates.

Two reasons the new name is better. `draft: false` makes you reason through a double
negative to work out that a post is live, where `published: true` says it. And flipping
the default to `false` changes which mistake is possible: a post that says nothing now
stays off the site, so forgetting the line can no longer ship something half-written. The
opposite mistake, a finished post not appearing, is obvious the second you look at the
site. Verified by building a post with no flag at all — no route, no feed entry.

**Drafts must be excluded from all four of these, and it is easy to miss one:**

1. the blog index
2. **the RSS feed** — a leaked draft in the feed *is* publishing it
3. the sitemap
4. the post's own route (it should 404 in production, not render)

Visible in `astro dev` so Momin can preview, absent from `astro build`. Publishing then
means flipping one frontmatter field and rebuilding, which is exactly the flow he wants
to test.

## RSS — confirmed on

Previously open, now decided: **we add it.** `@astrojs/rss`, feed at `/rss.xml`, which
also closes the years-old 404 described in post 1. Post 1 appears in the feed; post 2
must not, until Momin flips it.

The feed is also the cleanest proof the draft filter works: if `/rss.xml` lists one item
and not two, drafts are correctly excluded.

## Order of work

1. Astro scaffold and content collection schema, with the draft field.
2. Post 1 written and rendering.
3. RSS wired, verified to contain exactly one item.
4. Post 2 written as a draft, verified absent from index, feed, sitemap and its own route.
5. Hand it to Momin to publish by hand.

All of this is structure and content. **None of it needs the visual design**, which is
still waiting on Momin's reference sites and hints.

## Post 2 — standing constraints. Read before editing `mealunits.md`.

Both posts are written. These are the rules that governed post 2, recorded because a
future pass would otherwise re-derive them or, worse, undo them. Confirmed with the
MealUnits maintainers, who read the draft against the clinical docs.

### Never name the prescribing doctor

Not in this post, not in a later one, not as a warm detail on a second pass. There is an
explicit ruling in MealUnits' `BACKLOG.md` T11: the name stays out until he has been asked
with the exact wording in front of him.

The reason is not privacy boilerplate. **Crediting a named physician on an insulin
calculator reads as clinical endorsement**, and if a dose goes wrong the professional
exposure is his, not Momin's. The post is currently clean on this. Keep it that way.

### "A family member", and nothing more

No name, no city, no relationship detail, no diagnosis attribution. Momin can add detail
himself if he wants it — the point is that he **adds** it rather than being relied on to
remove it. Do not put it in a draft and assume review will catch it.

### Never write the dosing formula out

Prose description only. No equation, no code block, no worked example. The post says so
explicitly, which is deliberate. Describing what the app computes is fine; giving a reader
something they could dose by is not.

### Never imply validation

"Not clinically validated or reviewed by anyone" is literally true and must stay literally
true. No softening, no "informally reviewed", no naming anyone who looked at it.

### Every table cell describes the program, not the condition

This is the subtle one, and it is the one the review caught. The guardrail table's "why"
column originally read *"a low is not a dosing problem"* for low readings. True, and
entirely about clinical reality rather than about software — the kind of sentence that
survives being screenshotted without the table around it. Rewritten to describe what the
program does and why it declines to act.

Apply the same test to any row added later: **would this sentence still read as a claim if
it appeared on its own?**

### The stacking window is a rule about this program

Source is Walsh 2014, quoted verbatim in MealUnits' `src/config.ts`: a duration "too short
such as 3 hours can hide insulin stacking and lead to hypoglycemic events". So the hazard
is real and named.

But that is **pump literature, and MealUnits is not a pump.** The post therefore frames it
as a property of this program — having no decay model, it cannot justify a shorter window,
so it does not offer one — rather than as a rule about insulin that a reader on a pump
might apply to themselves. Keep that framing.

### Re-check the language before publishing — `check-plan.py` may not be Python by then

**Added 2026-09-21 at Momin's instruction.** MealUnits intends to rewrite `check-plan.py`
in TypeScript or JavaScript at some point. The post names the file, describes it as Python,
and carries a `python` fenced code block with `--self-test` semantics in it.

So **before this post is published, confirm what that checker actually is.** If it has been
rewritten:

- change the filename wherever it appears in the prose
- re-language the fenced block from ```python``` to ```ts``` or ```js```
- re-check that `--self-test` is still the flag, and that the seed loop still has the same
  two branches (mutation-changed-nothing, and checker-did-not-notice)
- re-read it against the new source rather than translating the old snippet

This is not cosmetic. The post's whole argument is that you check instead of assuming, and
shipping a confident description of a file that no longer exists would undercut it in the
most embarrassing way available.

The same applies to `src/sw.ts`, `docs/PLAN.md` and `docs/CLINICAL.md` — every path the
post names is a path that could move.

### Do not put a number on the escaped checks

The self-test keeps finding checks that could never fail; the count goes up. The post says
"and it is still finding them" rather than quoting a figure, which stays true without
needing maintenance.
