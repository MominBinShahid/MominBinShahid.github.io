What IndexedDB taught me about the same-origin policy

2026·08·21 · 5 min · #javascript · #html

MealUnits is an insulin calculator I built for my brother. It is deliberately boring software: no accounts, no server, no sync — the food log, the carb ratios, the entire history live in IndexedDB on his device, because the only person that data belongs to is him. An app like that makes exactly one promise: the data is always there.

So the message I got one evening — “it’s all gone” — was the worst message that app can receive.

Nothing was lost

Every byte was exactly where the browser had put it. He hadn’t cleared anything, the OS hadn’t evicted anything, and my migration code hadn’t eaten anything (I checked twice 😅). He was simply standing at a different door.

That morning he had opened the app from an old link — same site, same screen, same everything, except the address bar said www. The app he had been using for months lived at the apex domain. Two URLs, four characters of difference, and IndexedDB treats them as strangers.

An origin is three things

The same-origin policy is one of the oldest load-bearing walls on the web, and it is stricter than intuition wants it to be:

Two URLs share an origin when the scheme, the host, and the port all match — exactly. Everything else, the path, the query, the fragment, your good intentions, is irrelevant.

IndexedDB is origin-scoped. So are localStorage, Cache Storage, service worker registrations, and the Origin Private File System. There is no “nearby storage” lookup, no fuzzy matching, no inheritance from a parent domain. https://www.example.com and https://example.com are two databases. http:// and https:// are two databases. A different port is a different database, as every developer discovers the day the dev server moves from :3000 to :5173.

Three ways to lose data that isn’t lost

  1. The scheme changes. You migrate to HTTPS and the new origin starts empty; the old database sits behind the http:// origin forever — reachable, and invisible.
  2. The host changes. Apex vs www., localhost vs 127.0.0.1 — the host is compared as a string, not resolved. Same machine, different worlds.
  3. The port changes. Two dev servers, two databases, one confused engineer at 1 a.m.

And the honourable mentions that aren’t the same-origin policy but wear its jersey: browser profiles, private windows, and in-app browsers. The browser inside a chat app is frequently its own storage universe — a link opened there writes to a database nobody will ever see again. Safari adds a rule of its own: script-writable storage can be evicted after seven days without interaction, unless the origin has been granted persistence.

What MealUnits does now

The fixes were far less code than the debugging. One canonical origin, enforced with a redirect at the edge — the apex is the only door, and every other spelling of the address forwards to it before a byte of JavaScript runs. Then, on the first meaningful write, the app asks the browser to take the data seriously:

// boot — know which door you came in through
const here = self.location.origin;   // scheme + host + port, nothing else
if (here !== CANONICAL_ORIGIN) {
  banner(`You're at ${here} — your history lives at ${CANONICAL_ORIGIN}.`);
}

// ask politely to be kept out of eviction sweeps
if (navigator.storage?.persist) {
  const kept = await navigator.storage.persist();
  const { usage = 0, quota = 0 } = await navigator.storage.estimate();
  console.info(kept ? "storage: persistent" : "storage: best-effort",
               `${(usage / 1024).toFixed(1)} KiB of ~${Math.round(quota / 2 ** 20)} MiB`);
}

And an export button. A file in the hand beats a promise in the address bar — the same history, serialised to JSON, saved wherever he likes. Local-first should mean the user holds the data, not the browser holds the user.

The wall is the feature

It is easy to resent a rule that just cost you an evening. But the wall that confused my brother is the only thing standing between an insulin history and every third-party iframe on the web. The same-origin policy never promised convenience; it promised that a random tab cannot read a medical log 🔒. I’ll take that trade every time.

He didn’t need a lecture on origins, though he got most of one anyway. He needed the app to have exactly one door. Now it does.
